# 赛题要求分析（2026-11-05 版通知）

## 1. 和之前假设相比，变了什么

| 项目 | 之前的假设 | 最新通知 | 对工程的影响 |
|---|---|---|---|
| 机械臂 | 自带 PiPER | 现场统一提供，按赛程轮流用 | 不能提前在比赛那台臂上调；所有参数必须可配置，现场只做少量示教和核对 |
| 相机 | 自带，型号待定 | 现场提供 1 台腕端“大白”深度相机（奥比中光 Dabai 系列），统一安装，**不得更换或调整**；没有全局相机；内参从 camera_info 读，标定文件和手眼参数**不提供**（答疑 Q5–Q9） | `camera.mount: eye_in_hand`；必须在调试时段用 calib_points 自己做手眼标定；驱动随官方镜像提供 |
| L1 | 小方块抓放 | “方块分类”：识别**指定目标**，放到**指定区域**，3 个 / 180 s | 需要颜色分类 + 类别到区域的映射，还要支持“只抓指定颜色 / 指定顺序” |
| L2 | 果蔬分拣 | 6 个 / 300 s，按类别放到对应位置 | 类别表和容器对应关系未公布，必须做成配置 |

| 计算机 | 自带 | 自带，组委会提供统一系统镜像、驱动、示例、样本集 | 程序要在 Ubuntu 22.04 / ROS2 Humble / Python 3.10 下离线运行，依赖越少越好 |

## 2. 计分规则带来的取舍

- 总分 = L1 + L2（各 10 分，两轮取最高）+ 探索赛 × 0.2（最多 2 分）。主赛道占 20/22，优先级明显更高。
- 未完成也按有效任务给分，**只有全部完成才有时间分**。所以先保证单个目标稳定成功，再提速。一个目标反复失败时，要放弃它去做别的，不能耗光整轮时间。
- 时间预算：L1 平均 60 s/个，L2 平均 50 s/个。按 30% 速度估算，一次完整抓放约 15–20 s，剩下的时间够每个目标重试 1–2 次。
- 正式计时后只能自主运行；每轮最多一次经裁判同意的重启 / 维修（≤3 min，计入本轮时间）。所以程序出故障时**停下并报告**，不自动重启、不自动续跑。

## 3. 最大的约束：几乎没有真机调试时间

真机时间主要在 11/12–13 的预约适配。工程按这个前提设计：

1. **仿真先把逻辑和几何验证完。** 仓库里有一个 RGB-D 渲染仿真（桌面、方块、果蔬模型、托盘、夹爪）和运动学仿真臂，能跑完整的 L1/L2 闭环并按真值打分。状态机、坐标变换、重试、超时、故障处理都在仿真里测，不占真机时间。
2. **现场只需要填参数和示教，不改代码。** 相机话题、外参、TCP、夹爪行程、速度、区域位置、类别映射都在 YAML 里。区域位置和观察位姿用拖动示教记录（拖着机械臂到托盘上方按回车），不依赖视觉标定精度。
3. **固定的现场流程**（见 `docs/现场流程.md`）：接线 → 自检 → 示教区域 → 悬停核对外参 → 空跑 → 正式跑。每一步都有工具，失败时提示原因。
4. **识别不依赖大量训练数据。** 物体分割只用深度（“高出桌面的东西就是物体”），不用学习；分类有三种可选后端：
   - `color`：HSV 颜色阈值，适合 L1 方块，现场 1 分钟可重新标定；
   - `knn`：颜色 + 尺寸 + 形状特征的最近邻，现场每类放几次就能学会，适合 L2 用的固定那批果蔬模型；
   - `onnx`：YOLO 检测模型，拿到官方样本集后训练，用 OpenCV 4.5.4 直接推理，不改系统 numpy。
5. **安全检查集中在一处。** 所有运动目标先过工作空间、桌面高度、姿态和逆解检查，不通过就不发指令；运动完成要同时满足“控制器报到位 + 位姿误差小 + 连续稳定”，不只看 `motion_status`。

## 4. 仍未知、要在 11/10 培训或技术附件里问清楚的事

| 问题 | 为什么重要 | 程序里对应的配置 |
|---|---|---|
| 相机具体型号、固定在哪（腕部还是支架）、驱动是 ROS2 还是 SDK | 决定坐标链和取图方式 | `camera.mount`、`camera.ros.*` |
| 官方标定给的是什么：相机到基座，还是相机到法兰 / TCP？矩阵方向？格式？ | 外参方向弄反，抓取位置会差几十厘米 | `camera.extrinsics_file`（支持 4×4、平移+四元数、xyz+rpy、handeye_calibration_ros JSON） |
| 深度是否已对齐彩色、单位、分辨率 | 不对齐会导致三维位置错 | `camera.ros.depth_registered`、`depth_scale` |
| 夹爪型号（70 mm 还是 100 mm 行程）、指尖到法兰的距离 | 决定能抓多大的物体、下探高度 | `robot.gripper.max_width`、`robot.tcp_offset` |
| L1 “指定目标”怎么给：颜色？顺序？现场口头还是文件？ | 决定启动参数 | `run_task --targets red,blue,green` |
| L2 正式类别表、每类放哪个容器、容器尺寸和位置是否固定 | 分拣映射 | `config/site/tasks.yaml` |
| 成功判定：抬起高度、放置边界、是否允许“掉进去” | 决定释放高度和放置方式 | `place.release_height` |
| 计时开始和结束的判定、是否允许计时前把臂移到观察位 | 启动流程 | `runner.start_on_enter` |
| 能否在预约时段采集和保存图像（用于训练 / KNN 示教） | 识别方案 | `capture`、`teach_classes` |

## 5. 主要风险和对策

| 风险 | 对策 |
|---|---|
| 官方外参格式或方向与假设不同 | 加载器支持多种格式；`calib_verify` 让机械臂悬停到检测到的物体上方 3 cm，肉眼核对；偏差大时用 `calib_points`（拖动示教 5 个点）现场重标，几分钟完成 |
| 物体边缘深度噪声导致位置偏 | 多帧深度中值；几何用腐蚀后的掩膜；顶面取分位数 |
| 苹果、橙子等直径接近夹爪行程 | 规划时检查宽度，超过 `max_width - 5 mm` 不抓，并在日志写原因 |
| 红色类别相互混淆（苹果 / 西红柿） | KNN 用尺寸特征；有样本集时用 YOLO；低置信度标为 unknown，不乱放 |
| 现场 CAN、相机话题连不上 | `check_setup` 逐项检查并给出命令提示 |
| 官方镜像的 Python / numpy 版本不同 | 运行时只依赖 numpy、OpenCV、PyYAML、pyAgxArm，兼容 Python 3.8+ |
