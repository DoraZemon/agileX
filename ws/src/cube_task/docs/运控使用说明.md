# 运控使用说明

运控入口:`python3 -m cube_task motion_ctl <子命令> --mode <sim|mujoco|real>`。
不跑计时赛循环,单独驱动机械臂。所有动作都经过 `SafeArm`(工作空间、桌面间隙、倾角、关节限位、路径扫描),不绕过;工具退出时只 `stop`(保持姿态),**从不 `disable()` / `reset()`**。

## 1. 两种控制模式

| 模式 | 子命令 | 目标从哪来 | 谁规划 |
|---|---|---|---|
| 1 视觉目标接入 | `vision` | 相机 → 感知 → `Detection` | 任务自带的抓取/放置规划 + `PickPlaceSkill` |
| 1' 手填目标 | `pick` | 命令行手填基坐标 | 同上(同一条代码路径) |
| 2 MoveIt 拖动 | `moveit` | RViz 里拖动交互球 | MoveIt 规划,桥接节点执行 |
| 辅助 | `status` / `gripper` | - | - |

切换模式 = 换子命令,互不依赖。模式 1 与 2 不要同时对同一台真机运行。
视觉与运动的接缝:`Detection` → `TaskRunner.pick_detection()`。视觉只需产出 `Detection`(基坐标系的 xyz、top_z、尺寸、yaw、label),运动部分不关心它从哪来。

## 2. 环境(每个终端先做)

```bash
# 去掉 conda(它的 python3 会抢路径)
export PATH=$(echo $PATH | tr ':' '\n' | grep -v conda | paste -sd:)
unset CONDA_PREFIX CONDA_DEFAULT_ENV CONDA_PYTHON_EXE
export LC_NUMERIC=en_US.UTF-8
source /opt/ros/humble/setup.bash
source <仓库根目录>/ws/install/setup.bash   # 仅 moveit 需要
cd <仓库根目录>/ws/src/cube_task
```

`--mode mujoco`(带物理)用 `bash scripts/mujoco_run.sh motion_ctl ...`(venv,不支持 `moveit`)。

## 3. 模式 1:视觉 / 手填目标

```bash
python3 -m cube_task motion_ctl status --mode sim                 # 只读:健康、关节、TCP、夹爪
python3 -m cube_task motion_ctl vision --mode sim --list-only     # 观察并打印检测表,不动
python3 -m cube_task motion_ctl vision --mode sim --label red     # 观察 → 选目标 → 抓放
python3 -m cube_task motion_ctl vision --mode sim --count 3       # 连续 3 轮
python3 -m cube_task motion_ctl pick --mode sim --label red --xyz 0.30 0.05 0.05 --yaw 0.3
python3 -m cube_task motion_ctl pick ... --dry-run                # 只悬停到抓取位上方,不闭合、不抬起
python3 -m cube_task motion_ctl gripper --mode sim --width 0.08
```

- `--xyz X Y TOP_Z`:物体**顶面中心**在机械臂基坐标系下的位置(米)。`--size 长 宽 高`(默认 50 mm 立方块)、`--table-z`(默认取配置的 `expected_z`,否则 `top_z-高`)。
- `--label` 决定放置区(`class_to_zone`),也可用 `--zone` 指定。
- 规划失败或不可达时输出 `NOT PICKED: 原因`,不会动。
- 退出码:0 完成 / 1 没抓成 / 2 动作前被拒绝 / 3 故障 / 130 Ctrl-C。

## 4. 模式 2:MoveIt / RViz 拖动

需要两个终端(都先做第 2 节环境)。

终端 A:桥接节点(替代 ros2_control)

```bash
python3 -m cube_task motion_ctl moveit --mode sim              # 只规划,不执行(默认)
python3 -m cube_task motion_ctl moveit --mode sim --execute    # 真执行
```

终端 B:MoveIt + RViz

```bash
bash scripts/moveit_rviz.sh            # robot_state_publisher + move_group + RViz
bash scripts/moveit_rviz.sh --no-rviz  # 无界面(调试用)
```

RViz 里选规划组 `arm` 或 `gripper`,拖动交互球,点 Plan / Plan & Execute。

- **只规划模式**:桥接节点拒绝一切轨迹目标(日志 `trajectory goal REFUSED`),RViz 可规划、可预览,手臂不动。
- **`--execute`**:MoveIt 轨迹重采样成至多 24 个路点(`--waypoint-step`,默认 0.15 rad),逐点走 `SafeArm.move_joints`;任一点被拒绝则 `stop` 并返回失败。控制器在路点间自行插补,所以实际路径是规划路径的折线近似,**不是**逐点复现 MoveIt 的时间参数化轨迹;速度由 `--speed` 决定,不由 MoveIt 决定。
- 夹爪关节名 `gripper`,数值为开口宽度(m,0–0.1)。
- `scripts/moveit_rviz.sh` 里 `tcp_offset` 固定为 `[0,0,0.140,...]`,必须与配置 `robot.tcp_offset` 的 z 保持一致;现场量过 TCP 后两处一起改。
- MoveIt 不知道桌面和相机支架,RViz 里拖到桌面下方的目标会被 `SafeArm` 拒绝而不是 MoveIt 避开。
- 桥接节点已在 sim 中验证:反馈话题 `/feedback/joint_states` 正常,轨迹目标到达终点,只规划模式拒绝目标。真机未验证。

## 5. 上真机

本机没有 CAN 适配器和大白相机,以下流程**尚未在真机上跑过**,现场第一次请按顺序来。

1. 接线与急停:按下急停以外的东西都先不动;桌面空着,手放在急停上。
2. 拉起 CAN:`bash scripts/can_up.sh can0`(1 Mbps,需 sudo)。
3. 依赖:真机驱动走 `pyAgxArm` + `python-can`。`pyAgxArm` 目前**没有**装进 `venvs/piper`,系统 python 也没有 python-can;现场需把它们装进 venv(`third_party/pyAgxArm`),不要装进系统 python。
4. 自检:`python3 -m cube_task check_setup --live`。
5. 只读:`python3 -m cube_task motion_ctl status --mode real`(此时不使能)。
6. 第一次动:低速并先干跑。**最先做关节小步**(每个关节单次最多 0.10 rad,约 5.7°,越限会被 `SafeArm` 拒绝):
   ```bash
   python3 -m cube_task motion_ctl joints --mode real --joint 1 --delta 0.05 --dry-run   # 只检查
   python3 -m cube_task motion_ctl joints --mode real --joint 1 --delta 0.05 --speed 20     # 真动
   ```
   核对:动的关节、方向、角度和 `status` 读到的值一致。再做下面的:
   ```bash
   python3 -m cube_task motion_ctl gripper --mode real --width 0.05 --speed 20
   python3 -m cube_task motion_ctl pick --mode real --label <类> --xyz ... --dry-run --speed 20
   python3 -m cube_task motion_ctl vision --mode real --list-only --speed 20
   ```
   真机模式会先问 `yes` 才使能电机;`-y` 可跳过。`--speed` 超过配置值要加 `--allow-faster`。
7. 再去掉 `--dry-run`,速度逐步升到比赛值。
8. MoveIt 上真机:先 `moveit --mode real`(只规划),在 RViz 里确认手臂姿态与真机一致,再加 `--execute`,并且第一次只拖小幅度目标。

急停键(`pick` / `vision` 运行中):`p` 或空格 = 中止当前动作,`e` = 急停。

## 6. 现场必须先确认的参数

- TCP 偏移(配置 0.140 m,手册图 0.1425 m),实测后改 `robot.tcp_offset` 和 `scripts/moveit_rviz.sh`。
- 夹爪行程 100 mm(配置 `max_width` 已是 0.100;全开后用 `status` 核对读数)。
- 夹爪力单位(SDK 0–3 N,手册额定 40 N,未澄清);默认 L1 1.5 / L2 2.5。
- 机械臂怎么接:本工具只支持 `pyAgxArm` 直连 CAN;技术附件写笔记本“经 ROS2 网络接入” PiPER(话题名赛前公布),先问清是否还能接 CAN。
- 手眼外参:组委会不提供标定文件和手眼参数(答疑 Q8/Q9),在调试时段用 `calib_points` 自己标,再用 `calib_verify` 核对。相机只有 1 台腕端大白(`camera.mount: eye_in_hand`),内参从 `camera_info` 读。
- `observe_joints`、取物区、放置区坐标:用 `teach_poses` 示教。放置区是 3 张 200 × 200 mm 平铺卡纸,名字 `zone_green` / `zone_yellow` / `zone_red`,围边 0。

## 7. 常见问题

- `python3` 是 conda 的 3.13:没做第 2 节第一步;ROS 工具会报 `catkin_pkg` 缺失。
- `ModuleNotFoundError: rclpy`:没有 `source /opt/ros/humble/setup.bash`,或用了 venv python。
- `moveit` 报 `REFUSED ... supports --mode real or sim`:`mujoco` 模式不支持(rclpy 需系统 python)。
- move_group 日志里 `PointCloudOctomapUpdater` 的 ERROR:官方配置里的点云传感器插件缺失,不影响规划。
- 重建 ROS 工作区:去掉 conda 后 `colcon build --symlink-install --packages-up-to agx_arm_moveit --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3`。
