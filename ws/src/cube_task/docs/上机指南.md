# 上机指南（运控实机测试）

目标：按顺序确认连接、夹爪、关节、MoveIt、抓取都正常。**手始终放在急停上，桌面清空。** 以下流程在实机上还没跑过，每一步先看“期望”，不符就停下，不要往下做。

## 0. 环境（每个新终端只做一次）

```bash
cd <工程目录>/ws/src/cube_task
source scripts/env.sh
```

脚本做的事：去掉 conda、加载 ROS 2 和 `ws/install`、找到虚拟环境、进入 `cube_task` 目录，并提供 `$PY` 和简写 `ct`。之后所有命令都是 `ct <工具> ...`（等价于 `$PY -m cube_task <工具> ...`），与电脑无关。

- 期望：最后打印 `pyAgxArm: 可用`。
- 虚拟环境不在默认位置：`PIPER_VENV=<目录> source scripts/env.sh`。
- 必须用 `source`，用 `bash` 运行会被拒绝。
- MuJoCo 窗口：`bash scripts/mujoco_run.sh run_task --task L1 --mode mujoco --seed 1 --mount eye_in_hand --viewer --no-wait -y`。

## 1. 上电和 CAN

1. 机械臂上电，USB-CAN 接电脑，急停在手边。
2. 拉起 CAN（需要 sudo，别在有程序控制机械臂时运行）：
   ```bash
   bash scripts/can_up.sh can0
   bash scripts/can_up.sh --check      # 只读检查
   ```
   期望：`can0` 为 UP，1000000 bit/s。
3. 失败：`ip link` 看不到 `can0` → 检查 USB 线和适配器；有多个适配器 → 见 `can_up.sh` 头部注释里的官方脚本。

## 2. 只读：连接和状态（不使能）

```bash
ct motion_ctl status --mode real
```

期望：打印 6 个关节角、TCP 位置、夹爪宽度。**核对关节角和机械臂实际姿态一致**。
失败：`FAULT: cannot connect` → 回第 1 步。

## 3. 夹爪

```bash
ct motion_ctl gripper --mode real --width 0.05 --speed 20
```

期望：夹爪开到约 50 mm，终端提示 `yes` 才使能。再试 `--width 0.08`、`--width 0.02`。
力单位未确认（SDK 0–3 N，手册 40 N），保持默认小力，不要加大。

## 4. 关节小步（第一次动臂）

```bash
ct motion_ctl joints --mode real --joint 1 --delta 0.05 --dry-run     # 只检查
ct motion_ctl joints --mode real --joint 1 --delta 0.05 --speed 20    # 真动
```

- 每个关节单次最多 0.10 rad（约 5.7°），越限被拒绝。
- 期望：动的是 joint1，方向、角度和 `status` 读数一致。逐个关节试 1–6，每个先正向再反向回原位。
- 方向或关节号对不上：立刻停，不要继续。

## 5. 量 TCP，同步两处配置

量夹爪指尖中点到法兰的距离。与 0.140 m 不同时，**两处一起改**：

- `config/default.yaml` 的 `robot.tcp_offset`
- `scripts/moveit_rviz.sh` 里的 `tcp_offset` z

```bash
ct check_setup --task L1
```

期望：`tcp_offset` 一行 PASS。区域、外参等 FAIL 此时正常，下面第 8 步前补齐。

## 6. MoveIt / RViz

终端 A：
```bash
source scripts/env.sh
bash scripts/moveit_rviz.sh            # 无界面加 --no-rviz
```
终端 B：
```bash
source scripts/env.sh
ct motion_ctl moveit --mode real                 # 只规划，不执行
```

1. 在 RViz 里确认模型姿态和真机一致。
2. 拖一个小目标，点 Plan，确认轨迹合理。
3. 确认后再执行：终端 B 改为 `ct motion_ctl moveit --mode real --execute`，**第一次只拖很小的幅度**。

期望：运动平滑，`SafeArm` 拒绝时终端有提示。Ctrl-C 停止。

## 7. 手填坐标抓取

先把区域和桌面高度示教好（见第 9 步），再：

```bash
ct motion_ctl pick --mode real --label cube_red --xyz 0.30 0.05 0.05 --table-z <桌面z> --dry-run --speed 20
```

`--dry-run` 会运动到目标上方但不闭合夹爪。位置对了，去掉 `--dry-run`，速度逐步加到比赛值（超过配置值要加 `--allow-faster`）。

## 8. 视觉抓取（相机和外参就绪后）

```bash
ct motion_ctl vision --mode real --list-only        # 只看检测
ct motion_ctl vision --mode real --dry-run --speed 20
ct motion_ctl vision --mode real --speed 30
```

## 9. 现场参数清单

| 参数 | 位置 | 做法 |
|---|---|---|
| TCP 长度 | `robot.tcp_offset` + `moveit_rviz.sh` | 实测，两处同改 |
| 夹爪行程 | `robot.gripper.max_width` | 已是 0.100 |
| 夹爪力 | `config/default.yaml` | 单位未定，先用小力 |
| 观察位 `observe_joints` | `config/site/poses.yaml` | `ct teach_poses` |
| 放置区、取物区 | `config/site/` | `ct teach_poses` |
| 桌面高度 `expected_z` | `config/site/` | `ct teach_poses` |
| 类别到区域 `class_to_zone` | `config/site/tasks.yaml` | 照赛方给的映射 |
| 手眼外参 | `config/site/extrinsics.yaml` | 官方标定，或 `ct calib_points`、`ct calib_verify` |

参数写好后跑 `ct check_setup --task L1`（L2 同理），目标是没有 FAIL。

## 10. 急停和原则

- 运行中：`p` 或空格 = 中止当前动作并保持位置，`e` = 电子急停，`Ctrl-C` = 停止。
- 程序不会 `disable()` 或 `reset()` 机械臂，所有运动都经过 `SafeArm`。
- 同一时间只允许一个程序控制 CAN 上的机械臂。
- 出错就停，记下终端输出和 `~/vision_runs/` 里最新的日志目录。

## 11. 只有 1 小时的安排（实际用这个）

目标只是验证运控链路安全可用，不追求跑通完整任务。前一步没过就不做后一步，全程 `--speed 20`。

| 时间 | 做什么（对应第几步） | 通过标准 |
|---|---|---|
| 0–10 分 | 上电、`can_up.sh`、`status`（第 1–2 步） | 能连上，关节角和实际姿态一致 |
| 10–20 分 | 夹爪开合 0.05、0.08、0.02（第 3 步） | 开合正常，宽度读数合理 |
| 20–35 分 | 六个关节逐个 `--dry-run`，再每个正反各动 0.05 rad（第 4 步） | 方向、关节号、角度和 `status` 一致 |
| 35–45 分 | 量 TCP，不同于 0.140 就两处一起改（第 5 步） | `check_setup` 的 `tcp_offset` 是 PASS |
| 45–55 分 | MoveIt 只规划，再 `--execute` 拖很小的目标（第 6 步） | 模型和真机一致，动作平滑 |
| 55–60 分 | 记录问题，提交 `config/site/` 的改动 | 有可复现的记录 |

**这一小时不做**：第 7–8 步（`pick`、`vision`），它们依赖区域、桌面高度、外参和相机，现场还是空的。提前完成时，第一件往后加的事是示教区域和桌面高度（第 9 步）。

**卡住时**：
- CAN 5 分钟还连不上：停下排查（适配器识别、sudo），不要往后跑。
- 关节方向或编号对不上：最危险，立刻停，不做 MoveIt。
- TCP 提前用尺量好，到场直接改。

如果以后有 3 小时：在上表后面加“示教区和桌面 → 手填坐标 `pick` → `vision`”即可。
