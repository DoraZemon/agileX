# 上机指南（只有 1 小时）

目标：一小时内把**运控链路**验证到“可以安全地按坐标抓”，相机和视觉能做多少做多少。
**安全员的手始终放在急停上，桌面清空。** 以下流程在实机上都还没跑过：每步先看“期望”，不符就停，不要往下做。

更完整的资料：[运控使用说明](运控使用说明.md)、[现场流程](现场流程.md)（示教、外参、颜色标定、整轮限时）。

## 1. 一小时内能调什么

| 类别 | 内容 | 前提 | 本指南 |
|---|---|---|---|
| **必做（运控）** | 连接、夹爪、六个关节、TCP、MoveIt 拖动 | 只要有机械臂和 CAN | 第 3–7 步 |
| **有条件** | 相机话题、`view` 看画面、`check_setup --live` | 大白驱动已启动 | 第 8 步 |
| **有条件** | `teach_poses` 示教观察位、放置区、取物区 | 手能拖动机械臂，赛方给了区域 | 第 9 步 |
| **有条件** | `pick` 手填坐标抓取（先空跑） | 第 9 步做完 | 第 10 步 |
| **有条件** | `vision` 视觉抓取（先 `--list-only`） | 外参 `extrinsics.yaml` 已填 | 第 11 步 |
| **来不及，留到 11/13** | `calib_verify` / `calib_points` 外参、`color_calib`、`teach_classes`、整轮 `run_task`、L2 | 需要 10–30 分钟各一项 | 见 [现场流程](现场流程.md) 第 8–13 步 |

时间分配：**运控 0–40 分钟，其余 40–60 分钟**。运控没过，就不要做后面的任何一项。

## 2. 环境（每个新终端一次）

```bash
cd <工程目录>/ws/src/cube_task
source scripts/env.sh
```

脚本做的事：去掉 conda、加载 ROS 2 和 `ws/install`、找到虚拟环境、进入 `cube_task` 目录、提供 `$PY` 和简写 `ct`。之后所有命令都是 `ct <工具> ...`（等价于 `$PY -m cube_task <工具> ...`）。

- 期望：最后一行 `pyAgxArm: 可用`。
- 不可用：`$PY -m pip install -e <工程目录>/third_party/pyAgxArm`（装进虚拟环境，不碰系统 Python；换电脑要重做）。
- 虚拟环境不在默认位置：`PIPER_VENV=<目录> source scripts/env.sh`。
- 必须 `source`，用 `bash` 运行会被拒绝。
- 任何时候不确定参数：`ct <工具> -h`、`ct motion_ctl <子命令> -h`。
- 想先在仿真里熟悉命令：把 `--mode real` 换成 `--mode sim`，其他不变。

## 3. 上电和 CAN（5 分钟）

```bash
bash scripts/can_up.sh --check      # 只读检查，不用 sudo
bash scripts/can_up.sh can0         # 需要 sudo；没有程序在控制机械臂时才运行
```

- 期望：`can0` 是 UP，1000000 bit/s。
- 失败：`ip link` 看不到 `can0` → 检查 USB 线和适配器。5 分钟还不行就停下排查，不往后做。
- 有多个适配器：见 `can_up.sh` 开头注释里的官方脚本。

## 4. 只读状态（不使能，3 分钟）

```bash
ct motion_ctl status --mode real
```

- 期望：打印 6 个关节角、TCP 位置、夹爪宽度，**和机械臂实际姿态一致**。
- 失败 `FAULT: cannot connect`：回第 3 步。
- 可选，全面自检（只读、不动臂）：`ct check_setup --task L1 --live`。此时区域、外参、观察位这几项 FAIL 是正常的，只看 modules、can、ros、live 组。

## 5. 夹爪（5 分钟）

```bash
ct motion_ctl gripper --mode real --width 0.05 --speed 20
ct motion_ctl gripper --mode real --width 0.08 --speed 20
ct motion_ctl gripper --mode real --width 0.02 --speed 20
```

- 期望：先问 `yes` 才使能；夹爪开到约 50 / 80 / 20 mm，读数合理。
- 夹爪力单位没确认（SDK 0–3 N，手册 40 N）：只用默认小力，**不要加 `--force`**。

## 6. 关节小步（第一次动臂，12 分钟）

每个关节：先 `--dry-run` 检查，再正向、反向各动一次回原位。

```bash
ct motion_ctl joints --mode real --joint 1 --delta 0.05 --dry-run
ct motion_ctl joints --mode real --joint 1 --delta 0.05 --speed 20
ct motion_ctl joints --mode real --joint 1 --delta -0.05 --speed 20
# 对 --joint 2 ... 6 重复（注意先看 dry-run 输出的目标，越限会被拒绝）
```

- 单次每个关节最多 0.10 rad（约 5.7°），超过被拒绝；越关节限位也被拒绝。
- 期望：动的是对应编号的关节，方向、角度和 `status` 读数一致。
- **方向或编号对不上：立刻停，不做后面任何一步。**
- 回到指定姿态也可用 `--to q1 q2 q3 q4 q5 q6`（每个关节同样受限）。

## 7. TCP 和 MoveIt（15 分钟）

### 7.1 量 TCP

量指尖中点到法兰的距离。不是 0.140 m 就**两处一起改**：

- `config/default.yaml` 里的 `robot.tcp_offset`（`z`）
- `scripts/moveit_rviz.sh` 里的 `tcp_offset` z

```bash
ct check_setup --task L1 --skip can,ros
```

期望：`tcp_offset` 一行 PASS。

### 7.2 MoveIt 只规划，再小幅执行

终端 A：

```bash
source scripts/env.sh
bash scripts/moveit_rviz.sh          # 无界面加 --no-rviz
```

终端 B：

```bash
source scripts/env.sh
ct motion_ctl moveit --mode real                 # 只规划，不执行
```

1. RViz 里确认模型姿态和真机一致。
2. 拖一个小目标，点 Plan，确认轨迹合理。
3. 确认后终端 B 改为：`ct motion_ctl moveit --mode real --execute --speed 20`，**第一次只拖很小的幅度**。

- 期望：动作平滑，`SafeArm` 拒绝时终端有原因提示。`Ctrl-C` 停止。

**到这里（约 40 分钟）运控验证结束。** 以下按时间和条件取舍。

## 8. 相机检查（有条件，5 分钟，不动臂）

启动大白驱动（命令按 [现场流程](现场流程.md) 第 3 步，驱动已由工作人员启动则跳过）：

```bash
ros2 launch orbbec_camera dabai.launch.py depth_registration:=true
ros2 topic list | grep -E 'image|camera_info'
ros2 topic hz /camera/color/image_raw
ros2 topic hz /camera/depth/image_raw
```

- 期望：彩色、深度、内参三个话题都有数据。话题名不同时改 `config/site/local.yaml` 的 `camera.*`。
- 看画面（不动臂）：`ct view --task L1`；无显示器加 `--headless`。期望：每个物体一个实例，找到桌面。
- 录一些数据（可选，之后训练用）：`ct capture --session blocks_1112 --count 10 --interval 1`。
- 协作者的 `piper_vision` 包（相机配置、手眼标定、L1 识别）：
  ```bash
  cd ../piper_vision && python3 -m piper_vision show      # 打印相机配置
  python3 -m piper_vision l1                              # 从 ROS 话题取一帧做 L1 识别（未在真机测过）
  cd ../cube_task
  ```

## 9. 示教观察位、放置区、桌面高度（有条件，15 分钟）

赛方给了布局后做。工具本身不使能电机，用手拖动机械臂记录位置。

```bash
ct teach_poses --task L1            # 无显示器加 --headless
```

- 写入 `config/site/poses.yaml`：`observe_joints`、放置区、取物区；桌面高度在这里示教（`expected_z`）。
- 放置区 → 类别的映射写 `config/site/tasks.yaml` 的 `class_to_zone`（模板在 `config/examples/`）。
- 期望：区域都可达（OK 或 tilt）。再跑 `ct check_setup --task L1`，目标是没有 FAIL（外参一项除外，见第 11 步）。
- 拖动示教模式退不出来的处理，见 [现场流程](现场流程.md) 第 0 节第 6 条。

## 10. 手填坐标抓取（有条件，8 分钟，会动臂）

```bash
# 先空跑：运动到目标上方，不闭合夹爪、不抬起
ct motion_ctl pick --mode real --label red --xyz 0.30 0.05 0.05 --table-z <桌面z> --dry-run --speed 20
# 位置对了，去掉 --dry-run 真抓
ct motion_ctl pick --mode real --label red --xyz 0.30 0.05 0.05 --table-z <桌面z> --speed 20
```

- `--xyz` 是**顶面中心**在机械臂基座系的坐标（米）；`--table-z` 是桌面在基座系的高度。
- `--label` 决定放到哪个区域；也可用 `--zone <名字>` 直接指定。物体尺寸不是 50 mm 方块时加 `--size 长 宽 高`，倾斜加 `--yaw`。
- 速度要提到比赛值时才加 `--allow-faster`；这一小时不要提速。

## 11. 视觉抓取（有条件，7 分钟）

需要外参 `config/site/extrinsics.yaml`：赛方**不提供**（答疑 Q8/Q9），用 `bash scripts/handeye.sh` 自己标（拖动示教，指尖碰方块顶面中心，8 个点）。没标就**不做**本步。

```bash
ct motion_ctl vision --mode real --task L1 --list-only              # 只看检测，不动臂
ct motion_ctl vision --mode real --task L1 --dry-run --speed 20     # 悬停在目标上方
ct motion_ctl vision --mode real --task L1 --label red --speed 20   # 真抓一个
```

- `config/site/local.yaml` 现在把 `perception.backend` 设成 `l1_new`（协作者的 L1 识别，**未在真机验证**）。识别不对时对比原方法：加 `--set perception.backend=pipeline`。
- 期望：`--list-only` 里每个方块一条，坐标和实物相符，再进入空跑。
- 外参核对（会动臂，约 10 分钟）：`ct calib_verify --task L1`，通过标准见 [现场流程](现场流程.md) 第 8 步；放不下就留到 11/13。

## 12. 急停和原则

| 键（在运行 `pick` / `vision` 的终端按，不用回车） | 效果 |
|---|---|
| `p` 或空格 | 不再发新指令，原地保持（首选） |
| `e` | 电子急停，臂缓慢下沉，之后要放回支架并断电重启 |
| `Ctrl-C` | 停止并存日志；已发给控制器的那一条会走完 |
| 急停按钮 | 硬件急停，安全员负责 |

- 程序不会 `disable()` 或 `reset()` 机械臂，所有运动都经过 `SafeArm`。
- 同一时间只允许一个程序控制 CAN 上的机械臂；不要同时开两个会动臂的终端。
- 相机由工作人员安装，不要移动。外参（手眼标定）赛方不提供，自己用 `scripts/handeye.sh` 标。
- 出错就停，记下终端输出和 `~/vision_runs/` 里最新的日志目录。

## 13. 一小时时间表

| 时间 | 内容（第几步） | 通过标准 |
|---|---|---|
| 0–8 分 | 环境、上电、CAN、`status`（2–4） | 连上，关节角一致 |
| 8–13 分 | 夹爪（5） | 开合正常 |
| 13–25 分 | 六个关节小步（6） | 方向、编号、角度一致 |
| 25–40 分 | 量 TCP、MoveIt 规划再小幅执行（7） | `tcp_offset` PASS，动作平滑 |
| 40–45 分 | 相机话题和 `view`（8） | 三个话题有数据 |
| 45–52 分 | `teach_poses`、`check_setup`（9） | 区域可达 |
| 52–58 分 | `pick --dry-run`，再 `vision --list-only`（10–11） | 悬停位置对准 |
| 58–60 分 | 记录问题，提交 `config/site/` 改动 | 有可复现的记录 |

**卡住时**
- CAN 5 分钟连不上：停下排查适配器、sudo、`ip link`。
- 关节方向或编号对不上：最危险，立刻停，不做 MoveIt。
- 相机没数据：跳过第 8、11 步，用第 10 步手填坐标继续。
- 没有赛方布局：跳过第 9–11 步，把时间留给运控复测（MoveIt 多拖几个姿态）。

## 14. 一小时之后要补的（11/13）

外参核对 `calib_verify`、颜色标定 `color_calib`、L2 的 `teach_classes`、整轮 `run_task --dry-run` 再限时、L2 布局，见 [现场流程](现场流程.md) 第 8–13 步。
