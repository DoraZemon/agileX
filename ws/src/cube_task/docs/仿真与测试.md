# 仿真与测试

真机时间很少，所以逻辑、坐标变换、重试、超时和故障处理都在仿真里验证。本文说明仿真怎么工作、它能证明什么、
不能证明什么，以及怎么跑测试、批量仿真、回放和读日志。命令都在包根目录 `~/vision/ws/src/cube_task` 运行。

## 1. 仿真怎么工作

`--mode sim` 用的是和真机**同一套** TaskRunner、感知、抓取规划、抓放技能和 SafeArm，只把机械臂和相机换成仿真
版本，配置换成场景生成的配置（区域、标签、类别映射、取物多边形、外参、观察位）。

| 部分 | 文件 | 做什么 |
|---|---|---|
| 场景 | `sim/scenarios.py` | 按 `--task --seed --mount --difficulty` 生成摆放，结果确定（同样参数每次一样） |
| 世界 | `sim/world.py` | 纯几何：桌面在 z = 0，物体、区域（平垫子或带壁的容器）、夹爪 |
| 渲染 | `sim/render.py`、`sim/sim_camera.py` | 光线投射生成彩色 + 对齐深度，640x480，fx = fy = 380，加深度噪声和无效点 |
| 机械臂 | `robot/sim_arm.py` | PiPER 运动学（pyAgxArm 的 MDH 参数和关节限位）+ 时间模型 + 可注入故障 |
| 时钟 | `core/clock.py` 的 SimClock | 只有 `sleep()` 让时间前进，所以比实际快几十倍，而且每次结果一样 |

场景内容：

| 任务 | normal | hard |
|---|---|---|
| L1 | 3 个方块（红、绿、蓝，边长 31–40 mm），3 块彩色垫子 | 其中两个方块挨在一起，另加一个黄色干扰块（没有区域，不能抓） |
| L2 | 从 11 类（apple、orange、banana、lemon、grape、carrot、eggplant、cucumber、corn、tomato、green_pepper）里取 6 个，放进 fruit_bin / veg_bin 两个 5 cm 高的容器 | 物体间距更小，用全部 11 类 |
| L3 | 和 L2 类似（含 2 个苹果），3 个托盘，5 条中文指令和期望结果 | 同上，间距更小 |

相机安装：eye_to_hand 时相机在 (0.70, 0, 0.62) m，看向 (0.30, 0, 0)；eye_in_hand 时相机装在法兰 -x 方向 7 cm、
法兰面前 3 cm，光轴和工具 z 平行。

其他细节：

- 抓取成功的规则（`SimWorld.try_grasp`）：物体在 TCP 高度沿闭合方向的宽度小于张开宽度、TCP 在物体高度范围内、
  TCP 的 xy 在物体占地范围内（沿工具 x 8 mm，沿闭合方向半宽的 30 %）；手指碰到别的物体算失败（`collision_finger`）。
- 抓住的物体刚性跟着 TCP 走；张爪后物体竖直落到下面的区域底面或桌面上。
- 时间模型：每个运动 `robot.motion.sim_overhead_s`（0.35 s）+ 直线距离 /（0.15 m/s × 速度%）或关节角最大变化 /
  （2.0 rad/s × 速度%）；夹爪每次 0.6 s。
- 深度噪声：0.5 m 处标准差 0.8 mm，随距离平方增大；0.2 % 的像素无效。
- `--extrinsics-error M DEG`：给程序的外参加一个误差（平移 M 米、旋转 DEG 度，方向由种子决定），渲染仍用真实位姿。
  用它检验外参不准时的表现。
- L2 / L3 的 KNN 模型：第一次用时从 40 个仿真场景按真值标签训练，存在 `~/.cache/cube_task/knn_sim_<安装>_<哈希>.npz`。
  哈希来自 `cube_task/sim/*.py` 和 `cube_task/perception/*.py` 的源码，改了这些文件会重训一次（约 12 s）。旧文件
  不会自动删除（每个约 60 KB），可以手动删。

## 2. 仿真验证了什么、没验证什么

**验证了**：

- 状态机：观察、选目标、抓放、重试、黑名单、超时、没有目标时结束、故障时立即停下。
- 坐标链：两种相机安装、外参的各种写法和方向、TCP 偏置、桌面拟合。
- 安全检查：工作空间、桌面高度、姿态、逆解和关节限位。不可达的位姿不会发出去。
- 故障处理：抓空、掉落、运动超时、通信中断、相机丢帧（`sim_bench --faults`）。
- 指定目标、L3 指令解析和选择词（最左、最近……）、各工具的命令行流程。
- 感知几何：干净合成深度上的分割、尺寸、朝向、挨着的方块怎么切开。

**没验证**（只能在真机上看）：

- 物理：没有推动、滚动、滑动、碰撞反弹；物体放下后不会倒、不会弹出容器。
- 夹爪：几何满足就算抓住。真实手指的形状、摩擦、夹持力、物体变形、闭合时把物体推开，仿真里都没有。
- 真实深度：边缘飞点、反光或黑色表面没有深度、多路径、红外干扰。
- 颜色和光照：仿真颜色是理想的，HSV 区间必须在现场用 `color_calib` 核对。
- CAN 和固件：pyAgxArm 的实际时序、`motion_status`、使能要多久、急停后的行为。
- 机械臂精度、回差；真实的外参精度；ROS 驱动的行为。
- 用时：仿真的时间模型很粗，整轮时间以真机实测为准。

**仿真发现的 PiPER 可达性限制**（joint5 限位 ±70°，TCP 偏置 0.14 m）：工具竖直向下时，TCP 能到的最高位置很低，
离基座越远越低。用 `SafeArm.check_reachable` 在 y = 0、闭合方向沿 y 时算的结果：

| 离基座的水平距离 r | 0.15 m | 0.20 m | 0.25 m | 0.30 m | 0.35 m | 0.40 m | 0.45 m |
|---|---|---|---|---|---|---|---|
| 竖直工具 TCP 最高 z | 0.095 m | 0.105 m | 0.11 m | 0.105 m | 0.09 m | 0.065 m | 0.02 m |
| z = 0.15 m 需要的外倾角 | 25° | 15° | 10° | 10° | 10° | 15° | 20° |

所以预抓、转运、放置和观察这些高处的位姿要让工具向外倾斜（`task/reach.py`，最大
`robot.workspace.max_tilt_from_down_deg` = 30°），日志里会有 `decision action="tilt"`，检查里会有
`reachable with the tool leaned N deg`。抓取位姿能竖直就保持竖直。实际影响：区域要放在 r ≤ 约 0.40 m；腕部相机的
观察位要放低；在取物区最远的角上（r ≈ 0.45–0.50 m），连抓取位姿也要倾斜 5–15°。表里是闭合方向沿 y 的结果，
换闭合方向时数值会变。

```bash
cd ~/vision/ws/src/cube_task
python3 -m pytest -q -p no:cacheprovider test/                       # 全部，约 3 分钟
python3 -m pytest -q -p no:cacheprovider test/test_e2e_l1.py         # 一个文件
python3 -m pytest -q -p no:cacheprovider test/ -k extrinsics         # 名字里带 extrinsics 的测试
```

## 4. sim_bench：批量仿真

```bash
python3 -m cube_task sim_bench --tasks L1,L2 --seeds 0-19 --jobs 8
python3 -m cube_task sim_bench --tasks L1 --seeds 0-9 --mounts eye_in_hand --difficulty normal,hard \
    --faults none,grasp_miss,drop --json /tmp/bench.json
python3 -m cube_task sim_bench --tasks L2 --seeds 0-4 --extrinsics-error 0.003 0.5
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `--tasks` | L1、L2、L3，逗号分隔 | L1,L2 |
| `--seeds` | `0-19`、`3`、`0,5,7-9` | 0-9 |
| `--mounts` | eye_to_hand、eye_in_hand | 两种都跑 |
| `--difficulty` | normal、hard | normal |
| `--faults` | none、grasp_miss、drop、timeout、comm_loss、camera_none，每种故障在种子决定的时刻注入一次 | none |
| `--extrinsics-error M DEG` | 外参误差 | 0 0 |
| `--jobs N` | 并行进程数（20 线程的电脑用 8–16） | 1 |
| `--json PATH` | 结果文件；`-` = 打印到终端 | `~/vision_runs/sim_bench/<时间>.json` |
| `--save-logs` | 每一轮都写日志目录（慢一些） | 否 |
| `--config`、`--set`、`--log-dir`、`-v` | 同其他工具，作用于每一轮 | |

每一轮一行：任务、种子、安装、难度、故障、`placed`（程序认为放好的 / 要求的）、`ok`（按真值放对的）、`wrong`
（放错的）、`left`（还在取物区的）、用时、尝试次数、停止原因、结果（`OK` / `FAIL` / `!! WRONG` / `ERROR`）。
之后是按任务 / 安装 / 难度 / 故障分组的成功率、平均和最长用时、放错个数。

- **成功** = 要求的物体按真值全部放对、没有放错、在限时内。
- **放错**（物体进了错误的区域，或者非目标被放进区域）是最坏的结果，单独列在 `!! WRONG PLACEMENTS` 下，每一条都带
  一个复现命令（加了 `--save-logs`），照着跑就能拿到那一轮的完整日志。
- 退出码：0 = 没有放错也没有异常；1 = 有放错或异常；2 = 参数错；130 = Ctrl-C（已完成的轮次照样汇总）。
- 故障注入假设一次抓放大约 10 条机械臂指令；改了抓放技能的指令顺序后，故障落在哪个阶段会变（结果仍然固定）。

2026-11-06 的一次结果（L1 / L2 / L3，种子 0–9，normal + hard，两种安装，共 120 轮）：成功率 98 %，L1 平均 53–56 s，
L2 108–122 s，L3 93–100 s；有 1 次放错（L2 种子 6 eye_in_hand hard：KNN 认错了一个物体，茄子进了水果容器）。
数字会随代码变化，以当次运行为准。

## 5. 读日志

run_task 每一轮写一个目录 `~/vision_runs/<YYYYmmdd_HHMMSS>_<任务>/`（sim_bench 加 `--save-logs` 时也写）：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 一行一个事件（JSON）：`t` = 从日志创建起的秒数（用注入的时钟，仿真里是仿真时间），`wall` = 墙上时间，`kind` = 类型，其余是字段 |
| `obs_NNN.jpg` | 第 N 次观察的叠加图：实例掩码、标签和分数、被拒绝的实例和原因；选中的目标有黄框和 `TARGET <标签>`；左上角是任务、观察序号、轮内时间 |
| `report.json` | 本轮结果：放好个数、用时、停止原因、每次抓取一项 |
| `summary.json` | run_task 写：命令行、模式、速度、停止原因、退出码、仿真真值；`_logger` 里是事件数和写失败次数 |
| `config.yaml` | 本轮合并后的完整配置 |

运行时同样的事件也打印在终端，形如 `I cube_task.events: [  39.143] pick_result ok=true stage="done" ...`。

events.jsonl 里的 `kind`：

| kind | 什么时候 | 主要字段 |
|---|---|---|
| `run_task` | 摘要打印之后 | `summary`（摘要的每一行）、task、mode、dry_run、targets、speed_percent、argv |
| `precheck` | 真机：确认之前的完整自检 | ok、messages |
| `self_check` | TaskRunner 开始时的自检 | ok、mode、messages |
| `refused` | 没开始就停了 | reason（self_check / config / fault / aborted）、detail |
| `instructions_parsed` | L3：开始计时前解析的全部指令 | specs |
| `gripper_probe` | 启动前夹爪宽度检查（夹爪半开时再合拢 8 mm，看有没有夹着东西） | width、target、result、error |
| `start_lift` | 启动时 TCP 低于搬运高度，先竖直抬起 | ok、error、from_z、to_z、tilt_deg；不可达时 reason |
| `view_check` | eye_in_hand 真机：在观察位检查取物区看不看得到 | ok、message |
| `start` | 计时开始 | t0、deadline、required、order |
| `observe_move` | 去观察位 | ok、error、duration |
| `observation` | 每次取图 + 感知 | ok、n、detections（每个实例的 label、score、center_base、尺寸、valid、reject_reason）、warnings（含 `table z differs from the taught table ...`）；失败时 reason（no frame、stale frame、perception error ……）和 failures（连续失败次数） |
| `decision` | 每个决定 | action：`pick`（目标、区域、第几次、grasp_xyz、release_xyz、剩余时间）、`skip`（跳过的实例和原因 unknown_label / unmapped_label / zone_missing / not_a_target）、`blacklist`（放弃一个物体和原因）、`tilt`（各位姿的外倾角）、`nothing_to_pick`、`remeasure`（一帧的 too_wide / 几何缺失，下次观察再量）、`track_moved`（失败的抓取把物体推开了，沿用原来的尝试次数）、`observe_retry`（相机 / 识别失败后重试，wait 秒） |
| `skill_step` | 抓放的每一步 | stage、ok、error、duration；运动带 target、pos_err，夹爪带 command、width |
| `pick_result` | 一次抓放结束 | ok、stage、error、label、zone、duration、grasp_width、fault、holding |
| `instruction` / `instruction_result` | L3 每条指令的解析 / 结果 | label、selector、zone、count、ok、reason |
| `report` | 本轮结束 | 和 report.json 相同 |
| `close` | 日志关闭 | elapsed_s |

抓放的阶段（`stage`）：`open` → `pre` → `descend` → `close` → `lift` → `transit` → `release` → `open_release` →
`retreat`，成功时记为 `done`。空跑：`open` → `pre` → `hover_grasp` → `up` → `transit` → `hover_release` → `retreat`
→ `dry_run_done`。`recover_*` 是没抓住时的退回动作，`putback_*` 是抓着物体出问题时把它放回原处。

| 结果表里的 stage / error | 意思 |
|---|---|
| `grasp_miss` | 闭合后宽度小于 `robot.gripper.empty_width`：没抓住 |
| `dropped` / `dropped_in_transit` | 抬起后 / 转运后宽度变小：掉了 |
| `timeout` / `stalled` | 运动没在时限内到位 / 停在半路（可恢复，会退回并重试） |
| `unreachable` / `rejected` | 位姿够不到 / SafeArm 拒绝（工作空间、桌面、姿态） |
| `comm` / `arm_error` | 通信中断 / 控制器报错：故障，立即停 |
| `aborted` | 按了 `p`、`e` 或 Ctrl-C |
| `holding_object` | 夹着物体却放不下：故障 |
| `gripper_*`、`no_gripper_feedback` | 夹爪命令失败、没有宽度反馈：故障 |

停止原因：`done` 全部完成；`timeout` 剩余时间不够再抓一个（相机一直失败到时间用完也是 `timeout`，fault_detail 写
`observation failures: ...`）；`no_targets` 连续几次成功的观察都没有可抓的目标；`aborted` 操作员停止；`fault` 故障；
`self_check` / `config` 开始之前就拒绝了。

常用的查法（把 `$d` 换成日志目录）：

```bash
d=$(ls -td ~/vision_runs/*_L1 | head -1)
# 每次抓放的结果
python3 -c "import json,sys; [print(e['t'], e['label'], e['zone'], e['ok'], e['stage'], e['error']) for e in map(json.loads, open(sys.argv[1])) if e['kind'] == 'pick_result']" "$d/events.jsonl"
# 被放弃的物体和原因
python3 -c "import json,sys; [print(e['t'], e.get('label'), e.get('reason')) for e in map(json.loads, open(sys.argv[1])) if e['kind'] == 'decision' and e.get('action') == 'blacklist']" "$d/events.jsonl"
# 每次观察的警告
python3 -c "import json,sys; [print(e['t'], e.get('warnings')) for e in map(json.loads, open(sys.argv[1])) if e['kind'] == 'observation']" "$d/events.jsonl"
```

| 问题 | 先看 |
|---|---|
| 抓偏了 | obs_*.jpg 上目标框的位置；`decision action=pick` 的 grasp_xyz 和实物位置比；再做 calib_verify |
| 认错了 | `observation` 里的 label 和 score；obs_*.jpg |
| 某个物体一直不抓 | `decision action=skip` 的原因（标签没映射、不是目标）或 `blacklist` 的原因 |
| 用时太长 | `skill_step` 的 duration：哪一步慢；`pick_result` 的 duration |
| 仿真里放错 | 用 `!! WRONG PLACEMENTS` 下的复现命令跑一次，它的 summary.json 里 `placements` 是每个区域里实际的物体，和 `pick_result` 的 label 对比 |

## 6. 回放现场数据

`capture` 存的目录可以离线反复用。每帧有 `NNNNNN_color.png`、`NNNNNN_depth.png`（16 位，毫米）和
`NNNNNN_meta.json`（内参、时间戳、会话名；连着臂时还有关节角、T_base_flange、T_base_tcp）；加 `--npy` 时还有浮点
深度 `NNNNNN_depth.npy`，回放时优先用它。

```bash
# 现场采集（不动臂；臂可以在拖动示教模式）
python3 -m cube_task capture --session blocks_1112 --count 10 --interval 1
# 回去以后：看感知结果，每帧一行，最后打印检测表
python3 -m cube_task view --mode replay --replay-dir ~/vision_data/20261112_blocks_1112 --task L1 \
    --count 10 --headless
# 在回放的图上空跑完整的规划：选目标、抓取 / 放置位姿、可达性（只适合 eye_to_hand）
python3 -m cube_task run_task --task L1 --mode replay --replay-dir ~/vision_data/20261112_blocks_1112 \
    --dry-run --set camera.file.repeat=3
# 用采集的数据训练 KNN（每个类别一个目录）
python3 -m cube_task teach_classes --task L2 --from-dir ~/vision_data/20261112_apple ~/vision_data/20261112_banana
```

- replay 模式和真机一样读 config/site（外参、取物多边形、区域、模型），所以 config/site 要和采集时一致。
- 腕部相机的帧带着采集时的法兰位姿，view 用它算相机位姿。run_task 的回放用仿真臂当时的位姿，所以只适合 eye_to_hand。
- 真机的深度本来就是整数毫米，存成 PNG 不丢信息。仿真采集或 `capture --average N` 得到的深度有小数，PNG 会四舍五入
  到毫米，回放结果可能和现场不同（试过：一根玉米在回放里被分成两段）。这种情况采集时加 `--npy`。
- 用仿真数据演练这个流程：`capture --mode sim --task L2 --count 3 --npy --out /tmp/sim_capture --headless`。仿真不写
  config/site，回放时要用 `--set camera.extrinsics_file=<外参文件>` 给出仿真相机的外参。

## 7. 在仿真里演练现场工具

现场工具都支持 `--mode sim`：一个“仿真操作员”代替人拖臂、摆物体或量偏差（`[sim operator]` 开头的行），文件写到
`~/vision_runs/sim_site/`，不会碰 config/site。上机前每个工具至少演练一次，熟悉提示和命令：

```bash
python3 -m cube_task teach_poses --mode sim --task L1 --headless
python3 -m cube_task calib_verify --mode sim --task L1 --extrinsics-error 0.004 0 --all --apply --headless
python3 -m cube_task calib_points --mode sim --headless
python3 -m cube_task color_calib --mode sim --headless
python3 -m cube_task teach_classes --mode sim --task L2 --headless
python3 -m cube_task view --mode sim --task L2 --count 3 --headless
python3 -m cube_task capture --mode sim --task L2 --count 5 --out /tmp/sim_capture --headless
```

- calib_verify 在仿真里用真值当“测量结果”，提示时直接回车接受；`--extrinsics-error 0.004 0` 给外参加 4 mm 误差，
  可以看到修正量 d 约等于这个误差。
- teach_classes 在仿真里先用 `--sim-scenes` 个仿真场景按真值学习，`g` 按真值标注当前画面，`c` 重新摆放物体。
- color_calib 在仿真里会显示每个实例的真值（`sim truth` 一列），`c` 重新摆放方块。
- 写出的文件给别的工具用：`--config ~/vision_runs/sim_site/poses.yaml` 或
  `--set perception.classifier.knn.model_file=~/vision_runs/sim_site/knn_model.npz`。
