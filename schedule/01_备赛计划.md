## 1. 现状与前提

| 项目 | 现状 |
|---|---|
| 机械臂 | 官方提供 PiPER，到货时间未知 |
| 相机 | 技术附件指定的型号还没公布；手上有 Intel RealSense D435i |
| 工控机 | 最低配置还没公布 |
| 官方资料 | 已有 PiPER 用户手册和资料汇总（语雀）；11/10 培训会公布详细内容 |
| 本机 | Ubuntu 22.04.5、ROS2 Humble、RTX 3060 Laptop 6GB、i9-12900H；Python 环境已整理好，见 02 技能 0 |
| 时间 | 工作日每天至少 3 小时，周末每天至少 5 小时；视觉和机械臂两条线都由你一个人做 |
| 个人基础 | C++ 较好，Python 能读写基础代码 |

10/30 从官方资料得到的新信息，改变了原来的计划：

1. **软件栈**：官方把 piper_sdk 和 piper_ros 标为“已停止维护”。推荐 **pyAgxArm**（Python SDK）和 **agx_arm_ros**（官方称为“首选 ROS 接口”），MoveIt2 用 agx_arm_ros 里的 agx_arm_moveit。主控固件 ≥ S-V1.8-8 时强烈建议用 pyAgxArm。
2. **相机多半装在腕部**：新版 100mm 夹爪带相机安装孔，安装时相机孔位一侧要和 J6 零点刻度同侧；官方还提供 D435i、D405、DaBai DC1 的标准支架模型；官方手眼教程的主要流程也是“眼在手上”。
3. **目标物**：官方说训练可以“参考小方块或易抓取的物品”。所以视觉主线改成传统方法（深度前景加颜色和几何），YOLO 降为备用线。
4. **欧拉角约定已由官方确认**：rx/ry/rz 是绕 base_link 的 XYZ 外旋，R = Rz·Ry·Rx，范围限制在 ±179°，RY = ±90° 时万向锁。
5. **最好找一台 Windows 电脑**：固件升级必须用官方 Windows 上位机；解除过载失能的官方流程也是在上位机上先点急停、再点恢复。切换从臂模式（`set_follower_mode()`）和设夹爪零点（`calibrate_gripper()`）用 pyAgxArm 也能做。
6. **机械臂可达范围有限**：J5 只有 ±70~75°，夹爪竖直朝下时 TCP 最高只有约 0.10–0.12m；竖直姿态下腕部相机离桌面最高约 0.21–0.33m，前倾约 30° 时可以到 0.40–0.45m。观察方式要据此设计，见第 4 节。

## 2. 培训前要问清楚的问题

在答疑群里问，或者留到 11/10 培训时问。按对计划的影响从大到小排序：

1. 比赛用的 PiPER 主控固件版本、夹爪是新版 100mm 还是旧版 70mm、夹爪是否标配、预计哪天拿到。
2. 指定的相机型号；是否必须用官方 D435i 标准支架装在腕部；相机线怎么走。
3. 官方统一镜像用哪套软件栈和版本，提供哪些示例程序；镜像是启动盘还是磁盘镜像，要装到什么硬件上。
4. 工控机最低配置；CAN 模块是否随机械臂提供。
5. 标准目标物：方块边长、颜色数量、材质（木头、塑料还是泡沫），有没有其他形状；会不会紧挨或堆叠；能否提前拿到同款。
6. L1 的“指定目标”怎么告知；开赛前通过配置文件选定目标算不算违规干预。
7. L1 的“指定区域”怎么标识（色纸、胶带还是画线）；L2 容器的内尺寸、高度、位置，以及类别和容器怎么对应。
8. 机械臂底座装在哪里、有没有垫高；桌面高度和颜色。
9. 夹爪的 force 参数用什么单位（驱动限制在 0.5–3.0，手册写额定 40N）。
10. “目标识别”“分类正确”怎么判分：看屏幕显示、看日志，还是只看最终放到哪里。
11. 能否在场地上贴 ArUco 码，能否使用示教点，能否自带补光灯。
12. 程序崩溃后自动重启算不算违规；急停后恢复算不算一次维修；两轮之间能否改参数、重新标定。
13. 时间分怎么算，“全部完成”以哪个时刻为准；11/12–13 的适配试跑怎么预约。

## 3. 评分怎么拿

总成绩 = L1×40% + L2×60%。把各项折算到总分：

| 项目 | L1（×0.4） | L2（×0.6） | 合计 |
|---|---|---|---|
| 识别 / 分类（纯视觉） | 8 | 12 | 20 |
| 有效抓取 | 12 | 12 | 24 |
| 正确放置 | 12 | 24 | 36 |
| 完成时间 | 8 | 12 | 20 |

由此得出的策略：

- **L2 放置是最大单项（24 分）**。L2 分类一错，放置分通常也跟着丢，所以视觉准确率实际影响 36 分以上，外加 12 分时间分。
- **时间分只在全部完成时才有**。少做最后一个物体，除了丢它本身的分，还会丢掉整项时间分。所以先保证全部完成，再追速度。
- **两项各赛两轮取最高**。第一轮用稳妥档（速度 30–50%，开复看，每个物体最多试 2–3 次）；第一轮完成后，第二轮再换快速档。档位写在 config.yaml 里，开赛前只改一个参数，不改代码。
- **时间预算**：L1 每个物体平均 60 秒，L2 每个 50 秒。单次抓放控制在 20–25 秒，就能留出一次重试的余量。到货后要实测，见 03 的 P1 第 7 步。
- **判定条件留余量**：有效抓取要求离开支撑面 ≥30mm 并保持 ≥1 秒，按抬升 60–80mm、停留 1.5 秒以上来做；正确放置要求完全进入并稳定 ≥2 秒，按降到容器口以内再松爪、松爪后先竖直抬起再横移来做。
- **识别结果要能被裁判看到**：屏幕上实时显示检测框、类别、置信度和当前目标，同时写带时间戳的日志，申诉时也能当证据。
- **正式计时后不碰任何设备**。平时练习就执行“按下开始后双手离开”的纪律。

## 4. 技术路线

比赛用经典的模块化流程，不走模仿学习或 VLA。VLA 需要主从臂遥操作采集大量示教，换到赛场光照后成功率没有保证，两周里做不稳。

```
全局观察：相机前倾 15–30°、离桌约 0.40–0.45m，一帧看完工作区和容器
  → 识别：深度前景（高出桌面 ≥8mm）+ 顶面 Lab 颜色最近邻分类
          （外观复杂时换成 YOLO 分割，接口不变）
  → 选目标：手指落点空闲、顶面完整、尺寸检查通过
  → 复看：移到目标上方，相机光轴竖直，离桌 0.28–0.32m
  → 定位：顶面带（顶面以下 6mm 内的点）变换到基座系，在 XY 平面求 minAreaRect
          → 中心、边长、yaw（方块按 90° 对称折叠）
  → 执行（pyAgxArm）：预抓取位（顶面上方 5–8cm，不超过该半径的可达上限）→ move_l 下降 → 闭爪 → move_l 抬升 ≥60mm
          → 转运 → 放进容器槽位 → 抬升
  → 校验：夹爪开口判断是否抓到；回观察位复查是否放进容器；失败就重试
```

几个关键决定：

| 决定      | 选择                                                                      | 理由                                        |
| ------- | ----------------------------------------------------------------------- | ----------------------------------------- |
| 相机安装    | 默认 eye-in-hand（官方 D435i 支架）；eye-to-hand 代码保留备用                          | 新版夹爪带相机孔，官方有标准支架                          |
| 识别      | 传统方法为主线；YOLO 分割作备用线，先跑通一次                                               | 目标多半是彩色方块；传统方法不用标注，CPU 上毫秒级，几何精度高         |
| 定位      | 只用顶面带的点，在基座 XY 平面求 minAreaRect                                          | 相机倾斜时，用整个掩膜会把侧面算进去，误差约 2–16mm；用顶面带误差约 1mm |
| 比赛执行层   | 直接调 pyAgxArm：转运用 `move_p`，下降和抬升用 `move_l`                               | 依赖最少；用 SDK 直接判断到位，比 ROS 驱动 2Hz 的状态话题及时    |
| ROS 用在哪 | 相机驱动、RViz 可视化、MoveIt 仿真、官方手眼标定工具                                        | MoveIt 作为学习主线和仿真工具；比赛主流程不依赖它              |
| 比赛代码语言  | Python                                                                  | 官方 SDK 只有 Python 版；C++ 留给轨迹插值练习和赛后移植      |
| 手眼外参    | 统一存成 T_link6_color_optical，和 tcp_offset 无关                              | 官方工具的结果是相对 TCP 的，不换算的话容易差 13cm            |
| 版本      | 锁定 pyAgxArm d90e234、agx_arm_ros 286633e、handeye_calibration_ros 3f8e296 | agx_arm_ros 10 月中旬有不兼容改动；培训后再决定要不要跟随官方镜像  |

代码结构和各模块的接口见 03 开头的“比赛代码的结构”。

## 6. 任务状态机与容错

```
INIT 自检 → SCAN 全局观察 → SELECT 选目标 → RELOOK 复看 → GRASP 抓取 → VERIFY_GRASP 抓取校验
  → TRANSPORT 转运 → PLACE 放置 → VERIFY_PLACE 放置校验 → 下一个 / 重试 / 跳过
```

- **INIT**：检查 `candump can0` 有 2A1 帧、机械臂处于从臂模式、使能成功、夹爪反馈正常（`max_range_config` 和开口读数）、相机帧率，以及标定和配置文件已加载。
- **拍照前（SCAN 和 RELOOK）**：用 pyAgxArm 轮询 `get_arm_status().msg.motion_status == 0`，到位后再等 0.3–0.5 秒，丢掉前 3–5 帧。法兰位姿取同一段时间的平均值。夹爪保持固定开口，彩色图底部约 22% 被夹爪挡住的区域加掩膜。
- **SELECT**：L2 按“容易的先做”排序：手指落点空闲、顶面完整、尺寸检查通过、离容器近的先抓。已经在容器里的物体不再处理。
- **RELOOK**：移到目标上方，相机光轴竖直，离桌 0.28–0.32m。复看失败（深度成片无效、目标出画面）时退回全局观察的结果。
- **到位与可达**：`move_p` 和 `move_l` 之后都轮询 `motion_status`，并设超时（预计时长 ×2 + 2 秒）。arm_status 报 0x02（无解）或 0x04（目标角度超限）时换下一个 yaw 候选。不要用固定 sleep。
- **VERIFY_GRASP**：闭爪后读开口宽度，在“边长 ± 8mm”范围内算抓到。PiPER 夹爪行程中段有 7–10mm 的非线性误差，阈值必须用实物测。
- **PLACE**：按预先算好的槽位放，间距 ≥ 边长 + 25mm。方块底面降到容器口以下约 10mm 时松爪，松爪只开到“边长 + 20mm”，等 0.3–0.5 秒后竖直抬起。
- **VERIFY_PLACE**：回观察位拍一张，确认物体在容器里。
- **重试**：同一物体最多试 2–3 次，第 2 次换 yaw 候选；仍失败就先跳过，做完其他物体再回头处理。
- **看门狗**：主循环心跳停止超过 N 秒，强制进入恢复流程。

恢复流程要提前写好并演练（03 的 A8）：

- **CAN 失联**（报 SEND_MESSAGE_FAILED 或 ConnectionError）：先检查接线和航插，再确认机械臂不在主臂模式或示教模式。然后按官方 demo 的顺序恢复：`robot._set_leader_follower_config(linkage_config=0x00)` → 等 0.2 秒 → `set_follower_mode()` → `electronic_emergency_stop()` → 等 1 秒 → **托住机械臂** → `reset()`（会立刻掉电）→ 循环调用 `enable()`。
- **急停**：`electronic_emergency_stop()` 让机械臂带阻尼缓慢下落。ROS 的 `/emergency_stop` 是保持当前位置，两者不一样。断电（拔航插或断开 AC）会让机械臂立即掉落，只在紧急情况下用。
- **过载失能**（夹爪顶住东西、负载过大）：官方流程是在 Windows 上位机上点急停，把机械臂手动摆好，再点恢复；没有上位机时，按上面 CAN 失联的恢复顺序处理。下探时指尖离桌面至少留 5mm，避免过载。
- **程序崩溃**：用 shell 循环或 systemd 拉起。程序启动时先读夹爪开口，手里有物体就先放下；场景状态靠视觉重建，不依赖内存里的进度。自动重启算不算违规，要先问清楚。
- **3 分钟维修窗口**：维修时间计入本轮、不延长限时。只在系统彻底失效、剩余时间还够完成至少一个物体时才申请。你一个人操作时，恢复步骤要写在一张纸上，赛前用秒表演练 5 次以上。

已知的 PiPER 隐患：

- 外力超过关节保持力矩时（夹爪顶住桌面、撞到容器、手推已使能的机械臂），关节可能滑移，实际位姿偏离，但反馈不变、也不报错。运输后或被碰过后，先断电重启，再做对点验收。
- 标定不能在不同的机械臂之间复用。
- 不要同时运行两个占用 CAN 的程序，比如 agx_arm_ros 驱动和自己的 pyAgxArm 脚本。用官方工具标定时开驱动，比赛时只用自己的程序。
- 判断 CAN 是否还通，要看反馈数据是否在更新（`get_fps()` 或状态帧时间戳），不能只看 `get_arm_status()` 是否为 None，见 02 技能 6。

## 7. 检查清单

### 现场适配日（11/12–13）

1. 机械臂和底座紧固；相机支架螺丝紧固，用记号笔做位置标记。

8. 记录桌面高度、容器位置和放置区位置，写进 config.yaml。
9. L1、L2 各计时完整试跑至少 3 轮，记录用时和失败点。
10. 演练急停恢复、程序重启、拔插 CAN 恢复。
11. 设唯一的 `ROS_DOMAIN_ID` 和 `ROS_LOCALHOST_ONLY=1`；比赛时拔网线、关 Wi-Fi，避免和其他队伍的 ROS 话题互相干扰。

## 8. 一个人做两条线的注意事项

- 视觉和机械臂的接口只有两个：perception 模块输出的目标列表，以及 Executor 的方法。先把接口定死，两边可以分开调试。
- 每天结束前提交 Git。出问题时可以退回到前一天能跑的版本。
- 比赛当天如果有队友在场，把“启动和急停”交给一个固定的人；你看日志和调试画面。
- 有队友愿意帮忙时，最适合交出去的是：采购和 3D 打印、拍数据和标注（V6）、恢复流程演练和计时。

## 9. 主要风险与对策

| 风险                | 对策                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| PiPER 到货太晚        | 执行层先用 SimExecutor 和 dry-run 跑通；到货当天按 03 的 P1 做                                                      |
| 指定相机不是 D435i      | 视觉代码只依赖 ROS2 话题。换 RealSense 其他型号约半天；换奥比中光约 1–1.5 天（换驱动、开 depth_registration、核对内参、重新标定手眼）。技术附件一公布就动手 |
| 相机规定装在外部          | 切到 eye-to-hand：V2 的 T_cam_table 加上 TCP 触点法，感知层不改                                                    |
| 目标物外观复杂           | V6 的 YOLO 备用线提前跑通过一次，11/10 后切成主线                                                                    |
| 深色或亮面方块没有深度       | 用“桌面高度 + 已知边长”算 z，深度只用来定 xy                                                                         |
